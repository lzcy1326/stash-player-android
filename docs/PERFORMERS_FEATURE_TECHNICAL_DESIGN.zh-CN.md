# 移动端演员功能技术方案

日期：2026-11-05  
状态：功能范围已确认；本文供后续开发使用，尚未开始业务实现。  
依据：已查看的 Stash 真实演员列表、详情及筛选菜单，以及当前 Android 项目源码。

## 1. 目标和范围

首期打通“演员列表 → 演员资料与关联影片 → 现有影片详情/播放页”，保持当前播放器、续播、影片卡片及底部导航配置的使用习惯。

| 首期实现 | 后续功能 |
| --- | --- |
| 演员分页列表、搜索、筛选、排序、刷新 | 保存演员筛选方案及其同步 |
| 照片、资料、收藏与评分同步 | 图库、图片、合集、合作演员 |
| 关联影片搜索、筛选、排序、分页及播放 | 新增、资料编辑、删除、合并演员 |
| 返回恢复位置、弱网错误处理 | 自动刮削、提交 Stash-Box、厂商功能 |

后续内容不显示为空标签。当前交付仅为文档，不修改版本、不构建发布、不提交推送。

## 3. 页面和交互

### 3.1 演员列表

- 手机默认两列竖版照片卡片；平板根据可用宽度增加列数，保持卡片比例。
- 照片右上为收藏心形，右下为国家旗帜；下方显示性别图标、姓名、年龄与独立影片数量入口。
- 点击照片或姓名进入详情顶部；点击影片数量进入同一详情的影片区域，避免另建重复影片页面。
- 收藏、影片数量与整张卡片为独立点击目标，点击收藏不得同时打开详情。
- 无照片显示统一人物占位；未知性别使用中性标识，未知国家不显示旗帜；年龄不确定时隐藏，不能显示为 0 岁。
- 搜索姓名/别名；常用筛选为标签、评分、收藏、性别、年龄；更多筛选包含国家、影片数量、身高、职业时期、资料缺失。
- 常用排序为姓名、评分、影片数量、最新影片、播放次数、更新时间、随机；默认姓名升序。具体服务端映射按第 5 节核验。
- 筛选面板采用草稿，应用后统一刷新第一页；清空只清除当前演员列表条件。列表筛选与详情影片筛选各自保存。

### 3.2 演员详情

- 顶部紧凑展示照片、姓名、别名、性别、国家、年龄、评分和收藏。图片支持大图查看，长别名可展开。
- 生日、身高、三围、族裔、发色、眼睛颜色、职业时期、简介、标签、外链和 Stash ID 放入折叠资料区，空字段隐藏。
- 支持收起整个资料区，使影片列表尽早进入视野；由影片数量入口进入时，资料完成加载后不得抢回滚动位置。
- 影片总数、总时长、总大小优先使用服务端汇总；缺少汇总字段时显示可得数据，其余隐藏，不逐页下载全量影片求和。
- 资料与影片拥有独立加载状态、错误提示和重试按钮。资料失败不能阻塞已经取得的影片。
- 外链由系统浏览器打开，仅接受允许的网页协议，不携带服务端认证请求头。

### 3.3 关联影片

复用现有 `SceneCard` 与播放器入口，包括观看进度、影片本地收藏、稍后观看、队列及续播。演员服务端收藏与影片本地收藏保持各自的数据含义。

影片默认日期降序，支持现有可复用的影片搜索、筛选与排序。所有请求、重试、播放续页始终携带当前演员范围。清空用户条件后仍只显示该演员影片。

## 4. 模块与状态设计

建议新增以下文件，名称可在实施时按现有代码组织微调；不为该功能引入新的全局架构或依赖框架。

| 模块 | 职责 |
| --- | --- |
| `core/model/StashPerformerModels.kt` | 列表卡片、详情、分页结果、汇总数据模型 |
| `core/model/StashPerformerFilterModels.kt` | 演员查询条件、排序枚举、筛选草稿、有效性检查 |
| `core/network/StashPerformerQueries.kt` | 查询文本与变量构造；由现有客户端调用 |
| `core/network/StashPerformerParsers.kt` | 响应解析、空值兼容与更新结果解析 |
| `feature/performers/PerformersRoute.kt` | 列表状态及现有服务接入 |
| `feature/performers/PerformerDetailRoute.kt` | 资料与影片独立状态、播放回调 |
| `feature/performers/PerformerCard.kt` | 演员卡片、独立点击目标与无障碍描述 |
| `feature/performers/PerformerFilterSheet.kt` | 常用/更多筛选和排序界面 |

列表模型包含 id、姓名、别名、照片、性别、国家、出生日期、去世日期（若服务端提供）、评分、收藏、影片数。详情在此基础上扩展资料和汇总；不在列表请求完整影片或全部详细资料。

建议状态结构：

```text
PerformerListState
  query / appliedFilter / sort / direction / randomSeed
  items / total / nextPage / hasMore
  initialLoading / refreshing / loadingMore / error
  scrollAnchorId / scrollOffset

PerformerDetailState
  performerId / entrySection / infoExpanded
  profileState / scenePageState
  favoriteMutationState / ratingMutationState

PerformerSceneQuery
  scope: serverIdentity + performerId      // 固定范围
  query / userVideoFilter / sort / direction / randomSeed
```

状态按服务器身份与演员 ID 隔离。页面状态由页面状态持有者管理，沿用现有 Compose 状态组织方式；若使用 ViewModel，仅作用于该导航页面，不引入应用级单例状态。

导航保留 `performers`；新增建议路由 `performer/{performerId}?section={section}`，section 仅允许资料或影片两种入口。路由只保存 ID/入口，不传照片、完整资料和认证信息。

返回列表或从播放器返回时，恢复条件和滚动锚点。配置变化保存轻量状态；进程重建后按条件重新分页加载并恢复锚点，锚点消失时回退最近有效位置。不把整页响应塞入导航参数或保存状态 Bundle。

## 5. GraphQL 契约与验证门槛

### 5.1 已知与待核验分开

真实网页已证明演员列表、详情、收藏/评分、筛选和影片汇总能力存在；项目已有 `findPerformers` 和 `findScenes`。但本轮尚未逐项验证当前服务端完整 GraphQL schema，网页标签不能直接当作 GraphQL 字段名或排序字符串。

开发 MVP-0 必须先用只读 introspection 或网页实际请求确认以下内容，并将脱敏的字段映射和响应样例补入开发记录：

| 能力 | 必须确认的内容 |
| --- | --- |
| 完整演员分页 | 查询输入、分页总数、列表字段和照片地址 |
| 演员详情 | 单个演员查询参数、可空字段、别名、外链、标签、Stash ID 结构 |
| 姓名/别名搜索 | 通用 q 是否同时命中二者；否则验证服务端 OR 条件组合，禁止仅过滤当前页冒充全库搜索 |
| 演员筛选 | 年龄边界、标签组合语义、评分范围、收藏、性别、国家、影片数、身高、职业时期、资料缺失的输入结构 |
| 排序 | 每个产品排序对应的实际键、方向、空值顺序和随机种子机制 |
| 固定演员影片范围 | `scene_filter` 内演员条件的输入类型、modifier 和 AND 组合方式 |
| 汇总 | 影片总数、总时长/大小的字段、单位、统计范围及多文件计算规则 |
| 演员更新 | 更新 mutation 名称、input 类型、id、favorite、rating100 等实际字段及清空评分的表达方式 |

只读核验不执行真实更新。收藏/评分联调使用用户指定的测试演员，记录原始值，测试后恢复。

### 5.2 客户端接口建议

以下为 Android 内部接口意图，不是已验证的 GraphQL 签名：

```text
findPerformerCardsPage(listQuery) -> PerformerPage
findPerformerDetail(performerId) -> PerformerDetail
updatePerformerFavorite(performerId, desiredFavorite) -> 更新后的权威值
updatePerformerRating(performerId, desiredRatingOrNull) -> 更新后的权威值
findPerformerSceneCardsPage(performerSceneQuery, page) -> 现有影片分页模型
```

保留旧 `findPerformers` 供媒体选择器继续使用。新查询由 `StashGraphQlClient` 复用原有认证、网络调度和错误处理，不复制第二套 HTTP 客户端。

支持能力以当前服务端为基线；未知可选字段不得使最小列表/详情整体失败。兼容性通过已确认的基础字段和可选查询片段解决，不在每次失败时无限重试。若服务端缺少已确认首期的核心能力，应记录阻塞和替代方案，不能静默删减验收范围。

## 6. 固定演员范围和播放续页

推荐新增独立的 `PerformerSceneQuery`，避免把固定演员伪装成可被删除的普通筛选项。

1. 提取/复用现有影片变量构造和解析能力，在其基础上以 AND 语义合入固定演员范围；不能简单覆盖现有 `sceneFilter` 导致用户筛选丢失。
2. 演员范围不出现在可删除筛选芯片中；清空筛选只重置 `userVideoFilter`。
3. 给 `PlayerPlaybackQueueContinuation` 增加 `Performer` 类型，包含演员 ID、服务器身份、完整查询快照、下一页、页大小及 hasMore。
4. 更新该 sealed 类型全部分支，包括 `afterLoadedPage`、导航续页调度、随机播放处理与结束判断；不只增加数据类。
5. 播放入口传当前结果和查询快照，保持现有 `openPlaybackQueueScene` 路径。追加页按影片 ID 去重，空页结束，失败保留已加载队列并允许重试。
6. 随机排序使用已核实的服务端稳定种子，同一查询和续页不重新生成种子；刷新随机结果才生成新种子。不能在每一页各自洗牌冒充全库随机。
7. 后续页面修改筛选不改变已开始播放的队列查询。用户主动添加其他影片到全局队列仍沿用既有队列行为；自动续页不得混入其他演员。
8. 服务器切换时停止旧范围续页。首期沿用队列快照只恢复已加载项的能力，进程重启后不猜测原查询、不自动接成全库队列；如要持久化续页，另做版本化快照设计。

年龄用日期计算而非年份相减；只有出生年份时不伪造精确生日。存在去世日期时按已核验网页/服务端口径处理，并加入边界样例。

## 7. 收藏、评分和数据一致性

- 演员收藏和评分以服务端为准，写入成功后同步当前列表与详情缓存；失败恢复旧值并显示可重试提示。
- 同一演员同一字段的写入串行化；写入期间禁用该字段，避免旧响应覆盖新操作。收藏与评分分别提交最小更新字段，避免互相覆盖。
- 评分显示复用五星/半星，若确认服务端采用 0–100，则半星对应 10、整星对应 20；未评分与 0 分语义由 schema 和现有行为核验，不自行等同。
- 请求附带服务器身份和请求代次。旧服务器、旧演员或旧查询响应不得写入当前页面。
- 更新后重新进入页面读取服务端结果；在网页刷新确认一致。网络超时且写入结果不明时先重读权威值，再决定是否重试，避免无条件“反转收藏”。
- 影片收藏、稍后观看与队列继续使用当前项目存储和状态来源，不改为演员收藏接口。

## 8. 性能、弱网与安全边界

- 列表建议每页 40 项，首屏仅请求列表所需字段，禁止逐卡请求详情或影片形成 N+1。
- 详情资料和第一页影片并行加载，各自重试。进入影片区域无需等待照片下载或详细资料完成。
- 搜索建议约 300ms 去抖，查询变化取消旧请求，并以请求代次防止迟到结果污染状态。
- 翻页同一查询同时最多一个请求，成功后推进页码；失败重试原页。筛选变化清除旧分页并从第一页开始。
- 刷新时保留已显示内容，分别展示首屏错误、追加页错误和空结果；HTTP 错误与 GraphQL errors 均视为需要处理的结果。
- 演员照片复用现有图片加载及认证机制；缩略图按显示尺寸解码，大图按需加载。缓存按服务器隔离，凭据变化后失效，避免跨账号复用私有照片。
- 内存仅保留有界页面缓存，建议先以最近 5 页作为实现起点并验证回滚恢复；不靠扩大内存或拉取全库解决延迟。
- API Key 不进入文档、导航参数、持久化查询、截图或日志；不把认证头附加到外部照片域名和外链，图片请求沿用现有可信来源规则。
- 中文简体、繁体、英文及默认资源目录补齐同名字符串；错误信息、按钮、无障碍标签均用资源，不能硬编码中文。
- 心形、数量和折叠按钮可点击区域至少 48dp；大字体下姓名可换行，不能与心形/旗帜重叠。

## 9. 分阶段开发计划

每个阶段循环执行：实现最小可运行结果 → 针对性测试 → 安装用户安卓模拟器验收 → 记录结果 → 修复并重验 → 才允许提交。设备不可用或未通过时保留工作区，不跳过验收提交。真机验收补充触控和弱网感受，不替代约定的模拟器门槛。

| 阶段 | 详细工作与依赖 | 验收标准 |
| --- | --- | --- |
| MVP-0 接口契约 | 核验第 5 节全部首期字段；确认筛选/排序、照片认证、演员范围和汇总；建立脱敏 fixture 与转换测试 | 所有首期能力有准确字段映射；姓名/别名均能检索；只读核验不改数据；在模拟器确认既有应用启动和连接基线 |
| MVP-1 列表基础 | 新增列表模型/解析/接口；替换演员占位；卡片、搜索、姓名排序、分页、刷新、空/错状态 | 默认两列；只取当前页；快速搜索仅显示最后一次结果；追加失败可重试且无重复；收藏先展示真实状态，写入在 MVP-4 完成 |
| MVP-2 资料详情 | 新增详情路由、紧凑资料、折叠、大图、外链、汇总；数量入口定位影片区 | 空字段隐藏；资料独立重试；长姓名别名可读；入口定位不被异步资料打断；本阶段影片区允许开发中占位，最终不得保留 |
| MVP-3 影片与播放 | 固定演员查询、SceneCard 接入、独立影片加载；播放器及 Performer 续页上下文；搜索/筛选清空与返回恢复 | 仅当前演员影片；清空不丢范围；跨两页自动播放不串演员；进度/续播及卡片操作正确；返回恢复影片位置和条件 |
| MVP-4 筛选和同步 | 常用/更多演员筛选、完整约定排序；收藏与评分写回；列表详情同步及失败回滚 | 每个首期筛选/排序均有样例；网页刷新值一致；断网更新有反馈且状态恢复；连续操作和服务器切换无旧响应覆盖 |
| MVP-5 完整回归 | 横竖屏/平板/字体/语言；弱网、认证失败、分页边界、进程重建；性能测量与遗留问题清理 | 全部首期范围完成，无开发占位；模拟器通过全部关键路径；真机核查触控和图片；既有首页/探索/图库/播放器及导航配置无回归 |

每阶段记录：代码范围、测试命令与结果、设备标识、验收步骤、预期/实际、脱敏截图或日志、修复项与提交号。发现新问题回到当前阶段循环，不带已知关键问题进入下一阶段。

## 10. 测试和最终验收清单

### 10.1 有针对性的自动化测试

- 变量构造：演员范围与影片标签/评分/搜索正确组合；清空用户条件后演员范围仍在；原有首页/探索请求默认不增加演员范围。
- 解析：可空照片、未知国家/性别、空别名、长字段、无影片、部分汇总缺失和 GraphQL errors。
- 状态：去抖与旧响应、重复翻页、失败重试页码、刷新种子稳定性、服务器隔离、收藏/评分回滚。
- 队列：Performer 续页、重复影片去重、末页停止、续页失败恢复、查询快照不随页面变化、恢复快照不发全库请求。
- UI：卡片点击和心形/数量不冲突、折叠定位、返回恢复、大字体和独立错误区域。测试行为结果，不只对照组件内部实现。

### 10.2 模拟器必须覆盖的操作

1. 冷启动后从自定义底部导航进入演员页，原导航位置和设置保留。
2. 姓名与别名搜索，切换筛选排序，拉到第二页后刷新、返回并再次进入。
3. 从照片与数量分别进入详情；验证资料折叠、大图、外链、无照片/无影片状态。
4. 在演员影片内搜索、组合筛选、清空，核对结果始终属于当前演员。
5. 播放影片、续播、切换下一部直至跨页；检查播放上下文和返回位置；抽查收藏、稍后观看和手动队列。
6. 收藏与评分成功、失败、重试；网页刷新核对同步，再恢复测试原值。
7. 断网/恢复、延迟响应、授权失效、切换服务器，确认不闪退、不串数据。
8. 旋转屏幕、放大字体、切换语言和重建页面；检查条件恢复及布局。

### 10.3 性能衡量

性能结论必须带设备、网络、样本数和冷/热状态，不承诺不受服务器和外网影响的固定总耗时。

- 记录点击到加载反馈、列表响应、首批照片、详情资料和第一批影片可见时间，分别报告，避免只记一个“加载完成”。
- 同网络基线下各测至少 5 次并报告中位数和最慢值；检查客户端没有新增串行等待和逐卡请求。
- 点击后立即出现加载反馈；已有列表刷新不清空为长时间白屏。若服务端响应已返回而 UI 仍明显等待，必须作为客户端问题解决。
- 断网和超时后有明确重试入口，不能持续显示无期限“加载中”。
- 最终运行受影响单元测试、必要设备测试、Debug 构建和既有要求的静态检查；文档交付阶段无需运行构建。

## 11. 风险与完成判定

主要风险为服务端版本字段差异、随机跨页稳定性、固定演员与既有影片筛选组合、队列 sealed 分支遗漏、迟到响应覆盖状态，以及照片认证/缓存隔离。分别以契约核验、查询快照、组合变量测试、完整分支检查和设备弱网验收控制。

完成以所有首期能力可用、模拟器关键路径通过、测试记录可追溯为准。接口无法支持的核心项必须明确记录并重新确认处理方式；不能把未完成项写成“后续优化”后宣告完成。

当前交付到技术方案文档为止。后续开始实现时按 MVP 顺序推进，遵守模拟器验收后才提交的要求。
